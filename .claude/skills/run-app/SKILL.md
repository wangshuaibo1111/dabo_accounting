# 启动应用技能

当用户调用 `/run-app` 或说"启动应用""运行项目""跑起来""打开项目"等时，按以下流程执行。

---

## 执行流程

### 第 1 步：确认依赖安装 📦

检查 `node_modules` 目录是否存在：

```bash
ls node_modules/.package-lock.json 2>/dev/null && echo "依赖已安装" || echo "需要安装依赖"
```

- ✅ 依赖已安装 → 跳到第 2 步
- ❌ 需要安装 → 执行 `npm install`，安装完成后再继续

> 安装时给用户说一声："正在安装项目依赖，大概需要几十秒..."

---

### 第 2 步：确定端口并检查占用 🔍

先从 `vite.config.ts` 中读取实际端口号：

```bash
grep -oP 'port:\s*\K\d+' vite.config.ts
```

如果读到端口号就用它，否则默认 5173。

然后检查该端口是否被占用。

Windows：
```bash
cmd //c "netstat -ano | findstr :<端口号>"
```

- ✅ 端口空闲 → 跳到第 3 步
- ❌ 端口被占用 → 用 `npx kill-port <端口号>` 释放端口，然后继续

---

### 第 3 步：启动开发服务器 🚀

```bash
npm run dev
```

以后台方式运行，等待 3-5 秒后检查输出。

---

### 第 4 步：验证启动成功 ✅

检查 Vite 是否成功启动：

1. 查看后台输出中是否有 `Local:` 或 `http://localhost` 字样
2. 尝试访问 `http://localhost:5173` 确认响应

成功后告诉用户：

> "开发服务器已启动！在浏览器打开 **http://localhost:5173** 即可使用。"

并提醒用户：
> "按 `Ctrl+C` 可以停止服务器。"

---

## 常见问题处理

| 问题 | 处理 |
|------|------|
| `npm install` 失败 | 检查网络，尝试 `npm config set registry https://registry.npmmirror.com` |
| 端口被占用且无法释放 | 告知用户端口号，让用户手动处理 |
| 启动后报错 | 把错误信息展示给用户，分析原因 |
| 启动后页面空白 | 检查浏览器控制台是否有报错 |

---

## 禁止行为

- ❌ 不检查依赖就直接启动
- ❌ 启动失败不告知用户
- ❌ 占用端口不处理
